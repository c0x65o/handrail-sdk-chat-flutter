Root cause and reproduction

1. Browser focus is earlier than Flutter input readiness. In the retained
   current-qualified-browser.json, semantics on / 320, the destination DOM input
   receives Control+A and has selection [0,14] on keyup. The later snapshot has
   [13,13] in BOTH the DOM and Flutter controller. The protocol records a new
   TextInput.setClient and setEditingState with the pointer-selected [13,13],
   without an incoming accepted [0,14] update. The shortcut was delivered during
   the pointer-to-Flutter focus/input-connection handoff. This reproduces the
   selection-loss prerequisite for Preview's insertion into javascript:bad;
   that run stops on the failed assertion before typing the replacement.
   It is not evidence that the valid URL was rejected.

   The same rapid pointer/Control+A sequence in the existing plain Flutter
   TextField control (control=sync, no SDK composer/dialog) fails 1/12 attempts:
   javascript:badhttps://example.test/safe. All 12 attempts that wait for the
   field's actual Flutter/DOM readiness pass. See plain-field-control-browser.json
   and plain-field-control-320-false-1.png. This is a common Flutter/browser
   asynchronous input handoff, not Link-specific lifetime or sanitization code.
   The exact Preview concatenation was supplied by the owner, not recreated
   byte-for-byte here; original-preview-observation.txt preserves it explicitly.

2. After invalid Apply, the field loses Flutter focus and sends clearClient.
   Sending replacement keys without a normal field click leaves javascript:bad
   unchanged (legacy-keys-browser.json). The completed DOM focus transition alone
   cannot certify a Flutter connection. The final driver makes an ordinary
   pointer click and waits for matching controller/DOM selection and an active
   text-input client before sending keys. It never requests focus in Dart, calls
   DOM focus(), injects a controller value, or remounts the composer.

3. At 320px, keyboard traversal can horizontally scroll the toolbar so Link's
   full RenderBox starts at x=48 while the toolbar clip starts farther right.
   Clicking the un-clipped box center x=68 hits Add attachment. The retained
   current-connected failure includes Flutter's Attach focus and the rendered
   attachment-unavailable message. Final geometry includes the toolbar clip;
   ordinary wheel input exposes Link before clicking, and the dialog-open
   assertion must pass before any dismissal assertion. No product change or
   assertion suppression was used.

4. A generic input.last() synthetic-fill diagnostic selects a hidden submit
   input with semantics off and times out. Semantics-on synthetic fill did
   replace the URL and Apply successfully; that run later failed its unqualified
   selection/route assumptions. Do not report all synthetic fill as unsupported,
   or promote its false Escape success when no route opened. Final acceptance
   uses pointer + sequential key input, ControlOrMeta+A, Escape, Tab and Enter.
