## Root cause and production change

Published Flutter **0.1.31 / `51cf4d55ea147fd71267787b774585278ed1f55a`** disables its TextField while `_sending`. After a disabled frame, Flutter's TextField has set its FocusNode's `canRequestFocus` to false. Setting `_sending=false` schedules a rebuild; requesting focus immediately afterward still hits the disabled node and is dropped. The local draft-save failure path did not request focus at all.

The focus baseline includes the previously reviewed semantic/draft-echo fix, unchanged, with composer SHA-256 **`ce09e82b71238a641a5c3d17f78b75a1e63d35887605aae80cbf1557ed733295`**. The final composer is **`0ce967b86b4b1914c2eb3da4e8be3bc7be6f16819cacf91cdc7c6b0982cf36c6`**. `focus-only.diff` is the complete incremental production change: **57 added lines, 3 removed**, one file. Package version, lockfile, pure-Dart version mirror, native version-writer declaration, and original reviewed hunks are unchanged in the repository.

The success/queued branch, thrown/returned send-failure branches, and explicit local-save failure now await Flutter's `endOfFrame` before requesting focus. Local clear failure shares the success branch; later remote cleanup only reports draft status and never refocuses. Superseded operations release their sending state without restoring focus. No submission, retry, cancellation, draft-clear revision check, or transport identity policy was changed.

Restoration checks mounted/current binding, composition, captured actor and sticky identity-change state, exact client/destination/focus node, interaction availability, and the current operation/configuration generation. Changing enabled state, host controller, or host focus node invalidates old restoration. Actor subscriptions remain alive through the enabling frame. A temporary FocusManager listener respects another focus target, including focus movement from `onSent`; it permits the send/retry activation and Flutter's automatic return to captured ancestor scopes. Both scope fallback and button focus are important on CanvasKit. The two internal button FocusNodes are disposed with the composer. There is no polling or generic scheduler.
